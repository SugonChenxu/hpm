## M4 物料管理：修复需求清单"添加失败" + 需求清单支持 Excel 导入
- **Bug 根因**：多用户改造时 `db.js` 的 `OWNER_TABLES`（owner_id 补列清单）只含 `materials`，**漏了 `material_requirements`**。而 `server/src/routes/requirements.js` 的 `POST /requirements`（单条新增）与 `POST /requirements/batch`（批量导入）INSERT 都写 `owner_id` → SQLite 报 "no such column: owner_id" → 500 → 前端「添加失败」。批量导入同样会失败。
- **修复**：`db.js` 中 `OWNER_TABLES` 加入 `"material_requirements"`（服务启动即 `ALTER TABLE ... ADD COLUMN owner_id`）；并在 `CREATE TABLE material_requirements` 补 `owner_id INTEGER DEFAULT 0`（新库直接带列）。
- **需求清单 Excel 导入（新功能）**：
  - 原先「导入 Excel」按钮仅采购清单（`!isRequirement` 才显示）。现放开为两种清单都可导入。
  - `MaterialImportDialog` 新增 `mode` 属性（purchase/requirement）：需求模式用新增的 `parseRequirementExcel`（`client/src/utils/materialExcel.js` 新增 `REQ_FIELD_ALIASES` + `parseRequirementExcel`，`buildFieldMap` 改为可传自定义别名表），按需求列（模块/物料描述/物料号/预估单价/数量/物料状态/备注/OA链接）预览，提交到 `POST /api/requirements/batch`；采购模式不变。
  - `MaterialListPage.jsx`：移除导入按钮的 `!isRequirement` 限制，新增 `importMode` state 随清单类型切换，传给对话框。
- **验证**：DB 层 `PRAGMA table_info(material_requirements)` 确认已含 `owner_id`；`vite build` 通过；`forge` PM2 重启 online、0 重启；需求清单导出→导入表头可被解析器识别（往返 OK）。

## 备注：safe-delete 构建坑（可复用）
- Vite 8 + WorkBuddy 环境对 `fs.rmSync` 包了 genie-safe-delete（删除改移回收站）。清空 `dist` 时若回收站不可用会令 `vite build` 失败（prepare-out-dir 步骤）。**绕过法**：构建前用 OS `rm -rf client/dist` 先清掉，Vite 的 emptyDir 无文件可删即跳过回收站。

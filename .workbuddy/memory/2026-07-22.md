## M1 导出增强：Excel 日期联动公式（buildScheduleWorkbook）
- **需求**：导出 Excel 内「完成时间=开始时间+工期」「开始时间按依赖关系（含多重依赖）生成公式」。
- **公式规则（与 Forge 后端一致）**：
  - 完成时间 `=C{n}+E{n}-1`（工期按含首尾日历天数，故 -1）。
  - 依赖任务开始时间 `=MAX(各前置完成单元格)+1`；多重依赖取最晚结束项的次日。
  - 阶段任务：开始 `=MIN(叶子子孙开始)`、完成 `=MAX(叶子子孙完成)`，递归穿透子阶段。
- **关键实现**：日期以真实 Excel 序列号写入 + `numFmt=yyyy-mm-dd`；公式单元格写缓存结果 + `workbook.calcProperties.fullCalcOnLoad=true`（打开即重算）。
- **工程化**：抽出 `server/src/utils/scheduleExport.js` 的 `buildScheduleWorkbook(tasks, project)`；路由 `GET /api/projects/:id/schedule/export` 改为调用它。验证脚本（已删）回读 48 任务项目：38 叶子完成公式 / 36 依赖开始公式 / 10 阶段汇总公式全部命中。
- **注意**：工期约定为"含首尾"，若用户希望"完成=开始+工期"（间隔天数，不 -1），改 endCell 公式一行即可。

## PLM 扩展弹窗"复制无反应"修复（v0.1.1）
- **现象**：用户在 PLM BOM 页打开扩展弹窗，过滤后列表为空、点"复制响应/请求头"无反应。
- **根因**：① 3DEXPERIENCE 的 BOM 请求在 **iframe** 内发出，原 content_scripts 未设 `all_frames`，只注入顶层页 → 捕获为空；② 弹窗不自动刷新，打开后再浏览仍是空；③ MV3 service worker 内存存 `captured` 会被系统回收丢数据；④ cookie 用 `domain:'plm.sugon.com'` 可能漏掉 `.sugon.com` 域 cookie；⑤ `navigator.clipboard` 在弹窗内可能静默失败。
- **修复**：content_scripts 加 `all_frames:true` + 捕获范围放宽到页面所有非静态请求；捕获存 `chrome.storage.local`；cookie 域改 `sugon.com`；popup 每 1.5s 轮询 + 空列表提示；复制用 clipboard API 并回退 `execCommand('copy')` + "已复制 ✓"反馈；新增"复制为JSON"一次复制 URL+请求头+响应体；README 补"改码后扩展重新加载 + 刷新 PLM 页 + 保持弹窗打开"提示。三文件 `node --check` 通过。

## PLM 扩展"查看器始终一条捕获都没有"修复（v0.1.3）★根因级
- **现象**：重载扩展、独立查看器标签页也常驻了，但捕获列表始终空。
- **真正根因（经典 MV3 陷阱）**：content script 默认运行在 **isolated world**，其 `window.fetch`/`XMLHttpRequest` 与页面(MAIN world)的**不是同一对象**。原 content.js 在隔离世界重写 fetch/XHR，页面自己发的请求根本拦不到 → 永远零捕获。（与是否 iframe 无关，是世界隔离问题。）
- **修复（标准做法）**：拆成两个脚本——`inject.js` 用 manifest `"world": "MAIN"` 注入页面世界，真正拦截 fetch/XHR，捕获后 `window.postMessage({__forgePlmCap:true,data})`；`content.js` 改为隔离世界桥接，只监听 `message`（校验 `event.source===window` + `__forgePlmCap`）再 `chrome.runtime.sendMessage({type:'capture'})`。manifest content_scripts 两条目（MAIN 的 inject.js + 默认的 content.js，均 all_frames + document_start）。manifest 升 0.1.3。五文件 `node --check` + manifest JSON 校验通过。
- **`world:"MAIN"` 需 Chrome/Edge 111+**（用户较新版本 OK）；不受页面 CSP 限制（浏览器原生注入）。
- **若修复后仍空**：则确为**跨域 iframe**（BOM 接口在非 `*.sugon.com` 域，matches 注入不到）→ 兜底改用 DevTools Network 面板手动导出那条请求。

## PLM BOM 接口形态确认（用户从 DevTools 贴出真实请求）
- **关键发现**：PLM(3DEXPERIENCE) 的 BOM/物料数据**不是 JSON REST，而是服务端渲染 HTML 表格（JSP，嵌在 iframe 内）**。故适配器改为「持 cookie 抓 JSP → 解析 HTML 表格」，非解 JSON。
- **两条真实请求（用户提供）**：
  1. `GET /3dspace/common/emxExtendedPageHeaderAction.jsp?action=refreshHeader&objectId=<OID>` —— 对象属性头，`x-requested-with: XMLHttpRequest`，返回 HTML 片段。
  2. `GET /3dspace/SugonCentral/tableUI/tablefilter/sgDevelopmentWarehouse.jsp?objectId=<OID>&treeLabel=青柏&suiteKey=SugonCentral`（`sec-fetch-dest: iframe`，返回 `text/html`）—— **研发仓库/BOM 物料列表表**，这是目标数据所在。
  - `objectId`（如 `19520.49557.16852.46202`）是对象唯一 ID；cookie 含 `JSESSIONID=...cas03` + `afs=...`（与扩展 `chrome.cookies` 推的域一致）。
- **新增 `plm-bridge/capture.js`**（本机一次性采集脚本，零依赖）：读 `cookie.txt` 首行 cookie + `capture-urls.txt` 可选额外 URL，抓上述两页存 `captured/*.html` 并自动抽表格到 `*.tables.txt`；含登录失效检测（401/302/登录页）。`plm-bridge/.gitignore` 屏蔽 `cookie.txt`/`captured/`/`capture-urls.txt`。README 第四节改为 DevTools+capture.js 工作流。
- **下一步**：用户在办公机跑 `node capture.js <OID>` 把 `captured/` 给我 → 据此写 HTML 解析器 + `server/src/adapters/plm.js` 接入 M4 物料模块（持 cookie 经代理/直连抓 JSP、解析表格、owner 隔离、SSO 失效提示）。
